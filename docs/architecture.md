# Архитектура статического демо

```text
Учебные примеры / редактор JSON → JavaScript buildDigest → сводка в браузере
                                       ↕ CI: сравнение полных результатов
Локальный JSON → Python digest.build → Markdown / JSON
```

GitHub Pages обслуживает только HTML, CSS, JavaScript и готовые учебные данные. Backend обработки нет. Нажатие кнопки выполняет правила над текущим JSON в этой вкладке; изменённый ввод реально меняет результат и не передаётся на сервер.

Python CLI и JavaScript — две реализации одного описанного алгоритма. Python служит источником ожидаемых результатов для parity-матрицы: три основных сценария, различные типы операций/статусов/подтверждений, неизвестные и недостающие поля, противоречия, временные границы, ошибки и Unicode-ID. Каждое изменение обработчиков проходит сравнение полных структур результата и отдельные Python-тесты требований задания. Проверенная матрица не заменяет согласование бизнес-правил с отделом.

Сведения CRM и переписки передаются в результат отдельно. Внешних библиотек, LLM, API реальных сервисов, cookies и хранилища пользовательского ввода нет. HTML из источников показывается как текст, а не выполняется. Предпросмотр `python demo.py` собирает и обслуживает тот же Pages-артефакт только на loopback; расчёт остаётся браузерным.

Сборка использует явный список файлов и относительные пути к ресурсам: приложение работает в подпапке репозитория на github.io. CI проверяет Python, parity, статическую сборку и затем развёртывает готовый артефакт. Публичная версия не содержит конфигурации внешнего сервера или исходный документ работодателя.
