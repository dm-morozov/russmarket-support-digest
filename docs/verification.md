# Проверки

Python unit-тесты проверяют заданные четыре случая, приоритеты и действия, границу срока, отдельность источников, неизвестные статусы/подтверждения, противоречия, типы, произвольные ID, отсутствие мутации данных и сохранённую UTF-8-сводку. Отдельно проверяется формат календарных дат и ISO-времени.

`scripts/generate_parity.py` получает ожидаемые результаты непосредственно из Python на 317 входах, после чего Node.js сравнивает полный результат браузерного обработчика или факт отклонения ошибочного входа. В матрицу входят все три сценария демо, различные новые ID, перестановки состояний, отрицательные/положительные/неизвестные подтверждения, пропущенные/пустые/неверные поля, микросекунды, Z и разные UTC-смещения, Unicode-сортировка и ошибочные даты. Это покрытая тестами выборка, а не формальное доказательство эквивалентности на всех входах.

Сборка проверяется на разрешённый состав файлов и относительные ссылки, работоспособные в подпапке Pages. HTML из текстовых материалов экранируется. Фактический статус Actions, публичная ссылка и браузерная проверка указываются в итоговом отчёте после публикации.

Реальные CRM/чаты, полнота/свежесть выгрузки, автоматическое понимание текста, рабочие SLA и экономия времени не проверены. Данные примеров учебные, внешние интеграции не подключены. Серверные конфигурации и документ работодателя в публичный вариант не включаются.
